Demo Mode — How It Works Without Cloud Functions

With provider = "custom_video", the reward flow runs entirely client-side:

  1. User clicks a reward-locked prompt → unlock modal opens → video auto-plays muted.
  2. The adapter tracks real watch time (YouTube IFrame API / HTML5 timeupdate).
  3. When the user has watched for customVideoDurationSec seconds, the reward fires locally.
  4. Unlock is stored in localStorage (24h) and the prompt opens.
  5. Locked text is fetched directly from prompts_private/<id>/fullContent (rules must allow public read).

Trade-off: anyone who queries the database directly can read locked text without watching the video. For real production use, deploy Cloud Functions (/api/verifyReward + /api/getLockedContent), tighten prompts_private rules to ".read": false, and switch the provider to Monetag/Adsterra/AppLovin/Unity.
